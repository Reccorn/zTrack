# ТЗ: zTrack — личный офлайн таск-трекер с календарём

> Версия ТЗ соответствует zTrack **1.2.0** (02.10.2026).
> Документ описывает приложение так, чтобы его можно было воспроизвести с нуля на другом компьютере, другим разработчиком или ИИ-ассистентом, и получить тот же результат.

---

## 1. Назначение и цели

**zTrack** — настольное приложение для Windows для личного планирования: задачи, события, календарь, напоминания.

Ключевые цели:

1. **Полностью локально.** Без интернета, аккаунтов, облака и внешних API. Данные — один JSON-файл на диске пользователя. Даже ИИ — локальная модель через Ollama на том же компьютере.
2. **Удобный запуск.** Обычный `.exe` (установщик или portable), ярлык на рабочем столе и в «Пуске».
3. **Работа в фоне.** Сворачивание в трей, системные уведомления Windows, настраиваемый автозапуск.
4. **Быстрый и приятный интерфейс.** Тёмная тема по умолчанию, стиль Islands (как новый UI JetBrains / GitLab), крупные карточки в недельном календаре.

Вне рамок проекта: синхронизация между устройствами, совместная работа, мобильные версии, автообновление через интернет.

## 3. Модель данных и хранение

### 3.1. Типы (`src/shared/types.ts`)

```ts
type ItemType = 'task' | 'event'
type Priority = 0 | 1 | 2 | 3            // нет / низкий / средний / высокий
type RepeatFreq = 'none' | 'daily' | 'weekly' | 'monthly' | 'yearly'
type ThemeMode = 'dark' | 'light' | 'system'

interface Recurrence {
  freq: RepeatFreq
  interval: number          // каждые N дней/недель/месяцев/лет, ≥ 1
  weekdays: number[]        // для weekly: 0 — вс … 6 — сб
  until: string | null      // YYYY-MM-DD включительно
}

interface Item {
  id: string
  type: ItemType
  title: string
  notes: string
  date: string | null       // YYYY-MM-DD; null — «Входящие»
  time: string | null       // HH:mm; null — весь день
  endTime: string | null    // HH:mm, только для событий
  priority: Priority
  tags: string[]            // id меток
  reminder: number | null   // минут до начала; null — без напоминания
  recurrence: Recurrence
  done: boolean             // для неповторяющихся
  doneAt: string | null     // ISO
  completedDates: string[]  // для повторяющихся: выполненные вхождения
  excludedDates: string[]   // для повторяющихся: удалённые вхождения
  subtasks: { id: string; title: string; done: boolean }[] // шаги
  createdAt: string
  updatedAt: string
}

interface Tag { id: string; name: string; color: string }

interface Settings {
  theme: ThemeMode               // по умолчанию 'dark'
  launchAtStartup: boolean       // false
  startMinimized: boolean        // false — при автозапуске сразу в трей
  closeToTray: boolean           // true
  notifications: boolean         // true
  notificationSound: boolean     // true
  defaultReminder: number | null // 0 — «в момент начала»
  weekStartsOn: 0 | 1            // 1 — понедельник
  showCompleted: boolean         // true
  calMode: 'month' | 'week'      // 'week'
  sidebarCollapsed: boolean      // false
  aiEnabled: boolean             // true
  aiUrl: string                  // 'http://127.0.0.1:11434'
  aiModel: string                // 'gemma4:e2b-it-qat'
  aiEmbedModel: string           // 'embeddinggemma'
  aiKeepAlive: number            // 5 — минут до выгрузки модели
  aiSemanticSearch: boolean      // true
  aiVoice: boolean               // true
}

interface AppData {
  version: number                // 1
  items: Item[]
  tags: Tag[]
  settings: Settings
  notified: Record<string, number> // ключи уже показанных уведомлений → timestamp
}
```

**Вхождение (Occurrence)** — виртуальная пара «элемент + дата» для отображения: `{ item, date, done, key: "<id>|<date>" }`. Повторяющиеся задачи не размножаются в хранилище — вхождения вычисляются на лету.

### 3.2. Где и как хранится

| Что | Путь |
|---|---|
| Данные | `%APPDATA%\zTrack\ztrack-data.json` |
| Предыдущая версия | `ztrack-data.json.bak` |
| Повреждённый файл (если был) | `ztrack-data.json.broken-<timestamp>` |
| Ежедневные копии (14 последних) | `%APPDATA%\zTrack\backups\ztrack-YYYY-MM-DD.json` |
| Копия перед импортом | `backups\before-import-<timestamp>.json` |
| Данные режима разработки | `%APPDATA%\zTrack-dev\` (отдельно от рабочих!) |
| Индекс поиска по смыслу | `%APPDATA%\zTrack\embeddings.json` (векторы 256 float32 в base64; пересоздаётся) |

Требования к надёжности:

1. **Атомарная запись:** пишем в `*.tmp`, копируем текущий файл в `.bak`, затем `rename` tmp → основной.
2. **Восстановление:** если основной файл не читается — **всегда** сохраняем его копию `.broken-*`, затем пробуем `.bak`; если и он не читается — пустые данные (старый файл при этом не теряется).
3. **Нормализация при загрузке:** каждое поле проверяется и приводится к типу, недостающие настройки берутся из значений по умолчанию (так новые поля появляются без миграций).
4. **Уникальность меток:** метки с одинаковым названием (без учёта регистра) склеиваются при загрузке и импорте; у задач id дубликата заменяется на id оригинала.
5. При удалении программы данные **не удаляются** (`deleteAppDataOnUninstall: false`).
6. Переезд папки с исходниками на данные не влияет.

## 4. Функциональные требования

### 4.1. Задачи и события

- Два типа: **задача** (чекбокс-кружок) и **событие** (чекбокс-квадрат, иконка календаря, может иметь время окончания).
- Создание, редактирование, удаление, отметка «выполнено» — для обоих типов.
- **Удаление с отменой:** тост «Удалено: …» с кнопкой «Вернуть» (6 с).
- **Отметка с отменой:** тост «… — выполнено» с кнопкой «Отменить» (4 с).
- Задача без даты попадает во «Входящие». У события дата обязательна.

**Форма редактирования (модальное окно):**

| Поле | Поведение |
|---|---|
| Тип | переключатель «Задача / Событие» |
| Название | крупное многострочное поле, автофокус; Enter — сохранить |
| Дата | `<input type=date>` + быстрые кнопки «Сегодня», «Завтра», «+7 дней», «Без даты» (только для задач) |
| Время | переключатель «Весь день»; иначе начало (и конец у событий). При сдвиге начала конец сдвигается с сохранением длительности |
| Напомнить | Без напоминания / В момент начала / за 5, 10, 15, 30 мин / за 1 ч, 2 ч / за 1 день |
| Повтор | Не повторять / Ежедневно / Еженедельно (+ выбор дней недели) / Ежемесячно / Ежегодно; «каждые N»; «До» (дата окончания); человекочитаемая подпись «Каждую неделю: пн, ср» |
| Приоритет | Нет / Низкий / Средний / Высокий (флажки соответствующих цветов) |
| Метки | чипы-переключатели + «+ Метка» (создать прямо в форме) |
| Заметки | многострочное поле |
| Кнопки | «Выполнено/Вернуть» (для существующих), «Удалить», «Отмена», «Создать/Сохранить» |

Проверки: пустое название; конец раньше начала; «повторять до» раньше даты начала. Время/повтор/напоминание показываются только при наличии даты. Для повторяющихся показывается подсказка «Изменения применяются ко всей серии».

Горячие клавиши формы: `Ctrl+Enter` — сохранить, `Esc` — закрыть.

### 4.2. Разделы (левая панель)

| Раздел | Содержимое |
|---|---|
| **Сегодня** | группа «Просрочено» (неповторяющиеся невыполненные с датой < сегодня) + «Сегодня». Счётчик = просроченные + невыполненные сегодня; красный, если есть просроченные |
| **Календарь** | неделя-доска / месяц (см. 4.5) |
| **Предстоящие** | следующие 7 дней (завтра … +7), группа на каждый день, пустые дни — «Свободно» |
| **Входящие** | задачи без даты |
| **Все задачи** | «Просрочено» → группы по датам ближайшего вхождения → «Без даты» (выполненные не показываются) |
| **Выполненные** | выполненные неповторяющиеся + выполненные вхождения повторяющихся, сначала свежие; кнопка «Очистить» (удаляет выполненные неповторяющиеся после подтверждения) |
| **Метки** | список меток со счётчиками; клик — список задач с меткой |
| **Настройки** | внизу панели |

Навигация `Alt+1…6`. Переключатель «Выполненные видны/скрыты» в шапке разделов «Сегодня», «Предстоящие», «Входящие».

Левая панель сворачивается до иконок (ширина 60 px, счётчики — бейджи на иконках, метки — цветные точки): кнопка «‹‹/››» внизу или `Ctrl+B`. Состояние запоминается.

### 4.3. Быстрый ввод

Строка «Добавить задачу…» вверху списков, в панели дня и в колонках недели. Разбор текста:

| Ввод | Результат |
|---|---|
| `сегодня`, `завтра`, `послезавтра` | дата |
| `пн`…`вс`, `понедельник`, `в пятницу`, `во вторник` | ближайший такой день (не сегодня) |
| `12.10`, `12.10.2026`, `12.10.26` | дата; без года и в прошлом → следующий год |
| `18:30`, `18.30`, `в 18:30`, `в 18` | время |
| `!1`…`!3` или `!`, `!!`, `!!!` | приоритет |
| `#метка` | метка; новая создаётся автоматически |

Пример: `Позвонить маме завтра 18:30 !2 #семья`. Распознанные части показываются чипами справа. `Enter` — создать, `Ctrl+Enter` — открыть полную форму с заполненными полями, `Esc` — очистить. Если дата не указана — берётся дата контекста (сегодня / завтра для «Предстоящих» / нет для «Входящих» / день колонки).

### 4.4. Повторы — правила расчёта

Вхождение на дату `D` существует, если `D ≥ date`, `D ≤ until` (если задано), `D ∉ excludedDates` и:

- **daily:** разница в днях кратна `interval`.
- **weekly:** день недели `D` входит в `weekdays` (если пусто — день недели даты начала) и номер недели, считая от понедельника недели старта, кратен `interval`.
- **monthly:** разница в месяцах кратна `interval`; число = число даты начала, а если в месяце дней меньше — последний день (31 янв → 28 фев → 31 мар → 30 апр).
- **yearly:** разница в годах кратна `interval`, тот же месяц, число с тем же ограничением (29 фев → 28 фев в невисокосный год).

Разница в днях считается через `Date.UTC` — устойчиво к переходу на летнее время.

Отметка вхождения → дата в `completedDates`. Удаление повторяющегося: диалог «Только это» (дата в `excludedDates`) / «Всю серию» / «Отмена». Редактирование меняет всю серию. Повторяющиеся нельзя перетаскивать.

### 4.5. Календарь

**Неделя — основной вид (доска).** По умолчанию открывается неделя; выбранный вид запоминается.

- 7 колонок (с понедельника или воскресенья по настройке), минимальная ширина колонки 180 px; если окно уже — горизонтальная прокрутка. Каждая колонка прокручивается отдельно.
- Шапка колонки: крупное число, день недели, бейдж «сегодня», «N задач». Выходные — красноватый день недели, сегодня — акцентный цвет и подсветка колонки, прошлые дни — приглушённое число.
- Порядок карточек: невыполненные выше выполненных; внутри — сначала без времени, затем по времени, затем по приоритету.
- **Перетаскивание** карточки в другую колонку меняет дату, время сохраняется. Подсветка колонки при наведении.
- «+ Добавить» внизу колонки (появляется при наведении; у сегодняшней видна всегда) → компактный быстрый ввод. Двойной клик по пустому месту → полная форма на этот день.
- Пустая колонка — подпись «Свободно».
- Панель дня справа в режиме недели **скрыта**, чтобы колонки были шире.

**Карточка недели (главное требование к виду):**

| Элемент | Требование |
|---|---|
| Заголовок | 14 px, полужирный, **виден целиком** (перенос строк, без обрезки) |
| Заметка | первые **2 строки**, дальше многоточие |
| Время | вверху: `10:30–11:30`; «Весь день» у событий без времени; красное «Просрочено» у просроченных задач без времени |
| Приоритет | пилюля справа вверху: флажок + `!` / `!!` / `!!!` цветом приоритета; цвет рамки чекбокса = цвет приоритета; у высокого — дополнительная тонкая красная рамка карточки |
| Метки | полоса 5 px слева цветом первой метки (при нескольких — делится на равные части цветов всех меток), фон карточки тонирован цветом метки (~9 %), внизу — подписанные чипы меток с цветной точкой |
| Иконки | повтор, напоминание — в правом нижнем углу |
| Состояния | выполненная — прозрачность 55 %, зачёркнутый заголовок; наведение — тень и подъём на 1 px |
| Действия | клик — открыть форму; клик по чекбоксу — отметить; `Enter`/`Пробел` с клавиатуры |

**Месяц.**

- Сетка 6×7, название месяца + год, кнопки ‹ Сегодня ›, `Ctrl+←/→`.
- В ячейке — сколько поместится строк по высоте (рассчитывается через ResizeObserver), остальное «ещё N».
- Строка: точка/квадрат цветом метки, время, название. Перетаскивание между днями.
- Справа — панель выбранного дня (320 px): список задач, быстрый ввод.
- Двойной клик по дню — новая задача.

### 4.6. Метки

- Название уникально без учёта регистра (до 40 символов), цвет из палитры 10 цветов: `#7c5cff #38bdf8 #22c55e #f59e0b #f43f5e #ec4899 #14b8a6 #a3e635 #fb923c #94a3b8` (новой метке — следующий по кругу).
- Создание: «+» в разделе «Метки», в форме задачи, `#метка` в быстром вводе.
- Управление из боковой панели: кнопка «⋯» при наведении или правый клик → палитра цветов, «Переименовать», «Удалить». Двойной клик — переименование.
- Удаление: подтверждение (с числом задач с меткой), метка снимается с задач, тост «Вернуть» восстанавливает метку и её привязки.
- Дубликаты отклоняются на стороне хранилища (main-процесс), а не только в интерфейсе.
- Дублирующий список с переименованием, сменой цвета и удалением — в «Настройки → Метки».

### 4.7. Поиск

Поле в заголовке окна (`Ctrl+F`), ищет по названию, заметкам и названиям меток без учёта регистра. При поиске из календаря/настроек временно переключается на список; `Esc` очищает и возвращает предыдущий раздел.

### 4.8. Уведомления

- Планировщик в main-процессе, проверка каждые **15 с**, а также через 3 с после запуска и после выхода из сна / разблокировки.
- Кандидаты: невыполненные вхождения с напоминанием в окне [вчера … +2 дня].
- Время показа = начало − `reminder` минут. Задачи без времени — от **9:00**.
- Показываются напоминания, срок которых наступил **не более 60 минут назад** (закрывает случай сна ноутбука).
- Ключ показанного: `<id>|<date>|<time>|<reminder>` → в `notified`; ключи старше 7 дней удаляются. Изменение времени или напоминания «перевзводит» уведомление.
- При создании/изменении элемента не показываем «задним числом» напоминания о вхождениях, которые **уже начались**; если начало впереди, а время напоминания прошло — показываем сразу.
- Текст: заголовок — название; тело — «Событие/Задача · сегодня в 14:00–15:00 · через 10 мин» + первые 120 символов заметки.
- Клик по уведомлению — показать окно и открыть элемент.
- Настройки: вкл/выкл, звук, напоминание по умолчанию, кнопка «Тестовое уведомление».

### 4.9. Трей, окно и автозапуск

- **Одна копия приложения** (`requestSingleInstanceLock`); повторный запуск показывает окно.
- Закрытие окна при `closeToTray = true` — скрытие в трей; выход — через меню трея.
- Клик по иконке трея — показать/скрыть окно. Меню трея: «Открыть zTrack», «Новая задача», чекбоксы «Уведомления» и «Запускать вместе с Windows», «Выход».
- **Автозапуск настраивается** (настройки и трей): `app.setLoginItemSettings({ openAtLogin, path, args: ['--hidden'] })`. Для portable в `path` — `process.env.PORTABLE_EXECUTABLE_FILE`. В режиме разработки не регистрируется.
- «При автозапуске — сразу в трей»: окно не показывается, только если запуск с `--hidden` **и** опция включена.

### 4.10. Экспорт и импорт

- **Экспорт:** диалог сохранения, по умолчанию `Документы\ztrack-backup-YYYY-MM-DD.json`; содержимое — всё, кроме `notified`, плюс `app: "zTrack"`, `exportedAt`.
- **Импорт:** диалог выбора файла → проверка (должен быть массив `items`) → вопрос «Объединить / Заменить / Отмена» с числом задач и меток → копия текущих данных в `backups` → применение.
  - Объединение: по `id`, при конфликте побеждает более новый `updatedAt`; метки — добавляются отсутствующие; затем склейка дубликатов меток.
- Кнопка «Открыть папку данных».

### 4.11. Настройки

Разделы: **Внешний вид** (тема: Тёмная / Светлая / Как в системе; первый день недели; показывать выполненные), **Запуск и работа в фоне** (автозапуск; сразу в трей при автозапуске — неактивно без автозапуска; закрытие в трей), **Уведомления**, **Метки**, **Данные** (экспорт, импорт, папка данных, текст о локальном хранении и бэкапах), **О программе** (версия, горячие клавиши).

### 4.12. Локальный ИИ

**Основа.** Ollama на `aiUrl`, языковая модель `aiModel` (Gemma 4 E2B: текст + приём звука), модель эмбеддингов `aiEmbedModel` (EmbeddingGemma). Все запросы — из main-процесса (`src/main/ai.ts`), по одному (очередь), с таймаутом и отменой. Параметры генерации: `stream: false`, `think: false` (у Gemma 4 рассуждения включены по умолчанию), `keep_alive: "<aiKeepAlive>m"`, `temperature 0.2`, `num_ctx 4096`, ответ ограничен JSON-схемой через `format`. Модель ничего не сохраняет сама — только черновики/предложения, которые пользователь подтверждает.

| Функция | Как работает | Проверки после модели |
|---|---|---|
| **Разбор фразы** (`Alt+Enter`, «✨ ИИ») | системный промпт с сегодняшней датой и **таблицей ближайших 14 дней** (маленькой модели проще найти дату, чем считать), словарём времени суток (утром 09:00, после обеда 14:00, вечером 19:00…), списком меток и 2 примерами; схема без null — пустые строки и `reminder: -1` | дата/время по регэкспу; дата раньше вчера → отбрасывается; конец ≤ начала → убирается; есть длительность → событие; событие без конца → +60 мин; напоминание → ближайшее из допустимых; `-1` → напоминание по умолчанию; weekly без дней → день даты; дата начала weekly → ближайший подходящий день; метки — только существующие, остальные → «предложенные» |
| **Голос** | запись `MediaRecorder` → декодирование → `OfflineAudioContext` 16 кГц моно → нормализация громкости → WAV PCM16 → base64 → `/api/chat` с полем `images: [wav]` (так Ollama передаёт звук Gemma 4) и `options.thinking: false`; затем текст идёт в «Разбор фразы» | ≤ 30 с, ≥ 0,4 с; пустой или «could not transcribe» → понятная ошибка |
| **Шаги** («Разбить на шаги») | название + заметки + уже существующие шаги → `{ steps: string[] }` | 3–7 шагов, срезка нумерации, дубликаты убираются, ≤ 8 |
| **Ассистент недели** | неделя → текст: по дням «вт 6.10: N дел, ≈X ч»; короткие id `t1, t2…` — только у переносимых (неповторяющиеся задачи на сегодня и позже, просроченные); факты (сколько дел, самый загруженный день, просрочки) считает код и показывает сам — модель пишет лишь короткую оценку `comment`; день «загружен» от 4 дел или > 4 ч; без загруженных дней и просрочек переносы не запрашиваются (в схеме нет `moves`) | `id` и `to` — enum в схеме (`t1…`, коды дней `пн…вс` не раньше сегодня); перенос принимается, только если разгружает день (нагрузка цели + длительность < нагрузки исходного), ставит просроченное или переносит высокий приоритет раньше без ухудшения; `reason` и `comment` с упоминанием дней/дат (и `comment` с подсчётом дел) отбрасываются — подставляется текст от кода; до 5 переносов + до 3 советов; применение — только кнопкой, с проверкой, что задачу не перенесли вручную |
| **Поиск по смыслу** | при поиске (≥ 3 символа, задержка 600 мс) досчитываются векторы новых/изменённых задач (документ `title: … \| text: заметки; шаги; метки`, пачками по 16), запрос — `task: search result \| query: …`; векторы урезаются до 256 и нормируются (Matryoshka) | показываются совпадения со сходством ≥ 0,4, которых нет среди текстовых, до 8 |

**Настройки → Локальный ИИ:** включение, статус Ollama (`/api/version`, `/api/tags`), поля моделей с подсказками (`gemma4:e2b-it-qat` ≈ 4.3 ГБ, `gemma4:e4b-it-qat` ≈ 6.1 ГБ, `embeddinggemma` ≈ 0.6 ГБ), «Скачать» с прогрессом (`/api/pull`, потоковый NDJSON) и отменой, переключатели «Поиск по смыслу» и «Голосовой ввод», выгрузка модели (сразу / 1 / 5 / 15 / 30 мин), адрес Ollama, список установленных моделей с размерами и удалением (`DELETE /api/delete`, с подтверждением).

**Ошибки** показываются тостом по-русски: Ollama не запущена; модель не скачана (с подсказкой, где скачать); ИИ выключен; запрос отменён/долгий; непонятный ответ модели.

**Разрешения окна:** `setPermissionRequestHandler` разрешает только `media` (аудио) и `clipboard-sanitized-write`.

## 6. Архитектура

### 6.1. Процессы

- **main** — источник истины: хранит `AppData` в памяти, пишет на диск, планировщик уведомлений, трей, автозапуск, диалоги импорта/экспорта.
- **preload** — `contextBridge.exposeInMainWorld('api', …)` с типизированным интерфейсом `ZApi`. `contextIsolation: true`, `nodeIntegration: false`.
- **renderer** (Vue) — держит реактивную копию данных; любые изменения отправляет в main через IPC; main сохраняет и рассылает событие `data-changed` с полными данными. Оптимистичных локальных правок нет — единый путь данных.

### 6.2. IPC

| Канал (invoke) | Назначение |
|---|---|
| `data:get` | получить все данные |
| `item:upsert` / `item:restore` / `item:delete` | создать-изменить / вернуть удалённое / удалить |
| `item:toggle (id, date, done)` | отметить вхождение |
| `item:exclude (id, date)` | удалить одно вхождение серии |
| `tag:upsert` → `Tag \| null` | создать/изменить метку; возвращает существующую, если имя занято |
| `tag:delete` | удалить метку и снять её с задач |
| `settings:update (patch)` | изменить настройки (тема, автозапуск, трей применяются сразу) |
| `data:export` / `data:import` / `data:open-folder` | данные |
| `notify:test`, `app:version` | служебное |
| `ai:status`, `ai:pull`, `ai:delete`, `ai:cancel` | Ollama: статус, скачивание (прогресс событием `ai-pull-progress`), удаление модели, отмена |
| `ai:parse`, `ai:transcribe`, `ai:breakdown`, `ai:plan-week`, `ai:search` | функции ИИ; ответ `{ ok: true, data } \| { ok: false, error }` |

События main → renderer: `data-changed`, `open-item` (клик по уведомлению), `new-item` (пункт трея).

CSP в `index.html`: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:`. Внешние ссылки открываются в браузере, навигация окна запрещена.

## 7. Сборка, установка и обновление

### 7.1. Скрипты `package.json`

```json
"dev": "electron-vite dev",
"typecheck": "vue-tsc --noEmit -p tsconfig.web.json && tsc --noEmit -p tsconfig.node.json",
"build": "electron-vite build",
"build:win": "electron-vite build && electron-builder --win --x64"
```

### 7.2. electron-builder

- `appId: com.ztrack.app` — **совпадает** с `app.setAppUserModelId(...)`, иначе уведомления Windows не привязываются к приложению.
- `files: out/**, resources/**, package.json`; `asarUnpack: resources/**`; иконки импортируются как `?asset&asarUnpack`.
- Цели: `nsis` (`oneClick: false`, выбор папки, ярлыки на рабочем столе и в «Пуске», `zTrack-Setup-${version}.exe`) и `portable` (`zTrack-Portable-${version}.exe`).
- `npmRebuild: false`.

### 7.3. `build.bat`

Проверяет Node.js (иначе подсказка с адресом nodejs.org) → `npm install` → `npm run build:win` → открывает `dist`. Сообщения на русском, файл в CRLF и `chcp 65001`. `dev.bat` — запуск в режиме разработки (ставит зависимости при необходимости).

### 7.4. Обновление

1. Правка кода → проверка через `dev.bat` (данные отдельно, в `zTrack-dev`).
2. Поднять `version` в `package.json`, дописать `CHANGELOG.md`.
3. `build.bat`.
4. Закрыть zTrack через трей → запустить новый `Setup.exe` поверх. Данные сохраняются. Для portable — заменить файл.
5. Рекомендуется держать проект под git.

## 9. Известные ограничения и подводные камни

| Ситуация | Решение |
|---|---|
| Метка создавалась дважды: Enter прячет поле → `blur` вызывает сохранение повторно | флаг «уже сохраняется» в обработчике + защита от дубликатов в main |
| Уведомления не показываются | `appUserModelId` = `appId`; иконка уведомления — реальный файл (asarUnpack), не путь внутри `app.asar`; ссылки на объекты `Notification` держать до закрытия (иначе на Windows теряется клик) |
| Portable-версия иногда без уведомлений | рекомендовать установщик (он регистрирует ярлык в «Пуске») |
| Установщик NSIS не собирается на Linux | собирать на Windows (на Linux нужен wine); portable на Linux собирается |
| `Cannot create symbolic link` при сборке | включить «Режим разработчика» Windows или запустить от администратора |
| `.bat` ломается или кракозябры | CRLF-переводы строк, UTF-8, `chcp 65001` в начале |
| Поля даты в формате `mm/dd/yyyy` и 12-часовое время | `app.commandLine.appendSwitch('lang', 'ru')` до `ready` |
| Ошибка на смене летнего времени | разница дат через `Date.UTC`, а не деление миллисекунд локальных дат |
| Уведомления «задним числом» после создания задачи | `markPastAsNotified` при сохранении |
| Эксперименты в dev портят рабочие данные | `app.setPath('userData', …zTrack-dev)` при `!app.isPackaged` |
| Windows SmartScreen предупреждает | приложение без цифровой подписи: «Подробнее → Выполнить в любом случае» |
| Маленькая модель путает даты | таблица ближайших 14 дат в промпте + проверка и подстановки после ответа |
| Gemma 4 «думает» и отвечает медленно или пусто (особенно со звуком) | `think: false` и `options.thinking: false`; при ошибке про think — повтор без параметра |
| Ошибка `Float32Array` при чтении индекса | base64 → копия в отдельный `ArrayBuffer` (у Buffer из пула смещение не кратно 4) |
| Несколько запросов к модели одновременно раздувают память | очередь: одна генерация за раз |
| vite 8 / TypeScript 7 | несовместимы с electron-vite 5 / vue-tsc — держать vite 7 и TS 5.9 |

## 10. Как повторить

### 10.1. Человеку (по шагам)

1. Установить Node.js LTS и VS Code (или любую IDE).
2. Создать папку `zTrack`, `package.json` со стеком из п. 2.2, конфиги из п. 6.3 и 7.
3. Реализовать по порядку: `shared` (типы, повторы) → `main/store` → `main/index` + `preload` → `scheduler` → интерфейс (стили и токены → панель и заголовок → списки и быстрый ввод → форма → календарь → настройки).
4. После каждого шага — `npm run typecheck` и `dev.bat`.
5. Пройти чек-лист из п. 8, собрать `build.bat`, установить.
